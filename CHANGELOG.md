# Changelog

All notable changes to Coda are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project follows
[Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- `coda session fork` and a new `session.fork` request (capability `fork`, protocol version stays 1) start a new session from a turn of a Claude Code or Codex session. The fork has the backend, model, folder and mode of its parent and shares its folder, so only the conversation is copied, not the files. The database (schema version 23) keeps the parent and the fork point in a new `session_forks` table. Nothing starts until the first send to the fork, which tells the backend what the parent's turns up to the fork point said, as text up to 32 KiB, the way a rewound conversation is told; a fork of a fork is told the turns of its ancestors, at most 64 of them, as they were when each fork was made, so a later rewind of a parent changes nothing. After that first turn the backend keeps the fork's own conversation. A session on a model API cannot be forked yet, a session with a turn running is refused, and a rolled back turn cannot be a fork point. The native strategies (`--fork-session` for Claude Code, `thread/fork` for Codex) and switching a session to another backend are tracked separately.
- The terminal UI warns when a large session is likely to pay full price for its next message. After `cache_ttl_secs` (default 300) without a message or a turn end, a session whose context holds at least `cache_hint_tokens` (default 50000) shows `cache likely expired: the next message resends about 80k tokens, Tab to compact first`. Tab on an empty prompt compacts a Claude Code session through the new `session.compact` method (capability `compact`), which runs `claude -p /compact --resume <id>` in the session's folder. A live check with claude 2.1.296 found that `/compact` does nothing under `--disable-slash-commands`, which the `project` and `lean` profiles use, so the compaction is a call of its own. `session.resume` now also returns `updated_at`, the time of the session's last event (its creation time when it has none). The daemon does not record a compaction, so after a restart the hint can show again for a session that was already compacted; compacting twice only costs one more call.
- A new `fetch` tool lets a model-API session read one plain https page, from a host you list in the new `[fetch] allow_hosts` of `config.toml`, and it is off while that list is empty: the tool is not offered, a project or definition file cannot list a host, and Claude Code, Codex and sub-agent sessions never get it. `max_bytes` (default 256 KiB, at most 1 MiB) and `timeout_ms` (default 15 s, at most 120 s) bound a call. A session that offers it adds one sentence to its system prompt telling the model that text between the `untrusted content` lines is data, not instructions, and the page text comes back inside those lines. Every call asks for permission like a shell command, naming the address, and runs without asking only when you granted that address; `deny-all` refuses it. Before it connects, it refuses a name that has any non-public address, then connects only to the addresses it checked, and it refuses a redirect to another host. The threat model is in [docs/config.md](docs/config.md#fetch). There is no search and no login handling. This completes #238.
- A live probe of `claude --permission-mode acceptEdits` (claude 2.1.296) found that it writes `Cargo.toml` without a permission request (other files that change what runs were not probed). Coda therefore keeps `--permission-mode` out of the flags and decides accept-edits in its own gate, which still asks before a file that changes what runs (build files, hooks, CI workflows). The probe is in `crates/coda-providers/tests/live_probes.rs` and fails the day `claude` asks for such a file, so the mapping can be revisited. No behavior change.
- `/resume-at-reset [on|off]` in the terminal UI, and `session.resume_at_reset` over the protocol (capability `resume_at_reset`), make the daemon continue a session when a plan limit stops it. It is off by default and per session. When a turn ends at the limit and the provider named a reset time, the daemon waits for it (plus five seconds), then sends `Continue where you left off` with a request id made of the session, turn and reset time, so a repeat does nothing. A message that starts a turn, a queue resume, a stop, closing the session or turning it off cancels the wait, and a reset time that has passed is not waited for. The setting and the wait live in the daemon's memory, so a restart clears them.
- `coda` and `coda tui` on a terminal now offer to log in each enabled backend that is logged out, before the terminal UI opens, with the same question and vendor command as `coda login`. A declined or failed login does not stop the UI, a backend whose login cannot be checked is named on stderr, and no login is offered while `CLAUDE_CONFIG_DIR` or `CODEX_HOME` is set, since the login may live there. `coda login` also says when `CLAUDE_CONFIG_DIR` or `CODEX_HOME` is set in your shell, since coda sessions do not get it and would not see a login stored there. An opt-in live probe (`the_login_commands_exist_and_the_probes_read_the_installed_logins`) checks that `claude auth login` and `codex login` exist and that both login probes read the installed logins; the browser step stays a manual check.
- `coda session ship` (the `session.ship` request) commits what is staged in a session's folder (or every change with `--all`) with the message you give, and with `--push` or `--pr` also pushes the branch and opens a draft pull request, in one step. It runs `git` and `gh` in the session's folder as you, so your `gh` login applies and the commit is signed when your git is set to sign (it has a sign-off only when a hook of yours adds one, because Coda does not pass `-s`), it reads no token, never forces a push, and does nothing until you call it. It refuses while a turn runs, on a detached HEAD, when nothing changed and, for a push, on the default branch. A pull request it opens, or that a model-API session's agent opens with `gh pr create`, is linked to the session in a new `session_pull_requests` table (database schema version 21) and listed by `session.list` as `pull_requests` and by `coda session list`. A Claude Code or Codex session that runs `gh pr create` itself is not linked yet. The message is yours: generated text waits for the helper of #140.
- Cancelling a Claude Code turn no longer kills the process. Coda sends the `interrupt` control request, waits up to 2 seconds for the turn's `result`, and keeps the process for the session's next turn, so that turn skips a new process and a resume. A process that does not answer in time is killed as before, and so is one cancelled while a message is still being written to it. The daemon keeps the interrupted process in the idle pool, which a mode change, a rewind or a daemon stop empties. A completed turn still stops its process. A live check with claude 2.1.296 showed the process takes a new turn after an interrupt. No protocol change. See [docs/live-recording.md](docs/live-recording.md).
- `[review.watch] enabled` (off by default, global config only) makes a PR watch start `coda review --incremental` when the branch gets a push after the watch began, and wake the session with what the review printed. A draft, a merge commit and a commit by a bot start nothing, and a commit that could not be read is tried again at the next read. The review runs with your own `gh` login and ends after 15 minutes, and its output reaches the session as data cut at 8 KiB. See [docs/config.md](docs/config.md#reviewwatch).
- Scheduled prompts: `coda schedule add|list|remove` (the `schedule.add`, `schedule.list` and `schedule.remove` requests) have the daemon send a prompt once (`--in 10m`), on an interval of from 60 seconds to one year (`--every 1h`) or at a time of day in UTC on chosen weekdays (`--daily 09:30 --weekdays mon,fri`), into a session or into a new session made for each run. The rows live in a new `scheduled_prompts` table (database schema version 22). A run is claimed in one transaction that also moves its next time forward, so a tick never sends one twice, and a start puts back the rows a crash left running. They are bounded: at most 50 schedules, a tick sends at most 5 prompts, and `coda schedule list` shows each one. There are no webhooks yet.
- PR watch: `coda session watch <session> --pr <number or address>` (the `session.watch_pr` request) and, for model-API sessions, a `watch_pr` tool read a pull request every 2 minutes with your own `gh` and wake the session with a message when a check fails, the required checks pass, someone else comments or reviews, or the branch conflicts. Comments already there when the watch starts are not news, and news already reported is not repeated. A watch stops when the pull request is merged or closed, after 10 wakes in a row that held only comments, or after 8 failed reads in a row. A session may watch 5 pull requests and the daemon 32. A watch lives in the daemon and ends when the daemon stops. A Claude Code or Codex session can be watched through the command but has no tool of its own.
- The terminal UI shows the plan limit the provider last reported on the status line (the most used window, with what is left, the time to its reset and whether use is ahead of, on pace with or under the time gone), shows cache tokens, and `/limits` lists every window. `coda usage` counts cache tokens (the database keeps them from schema version 20; earlier rows count as zero) and ends with a `limit:` line for each window that has not reset. `usage.summary` gains an optional `limits` list.
- `coda_providers::claude_helper::run_structured` makes one cheap structured call of the installed `claude` for short jobs such as a session title, a commit message or a branch name: `claude -p` with a JSON schema, no tools, no settings, no MCP servers, no skills and no saved session, run from an empty temporary folder and stopped after 180 seconds. The prompt goes on standard input and the structured output comes back. On claude 2.1.296 it sent about 1.1k prompt tokens on `haiku`. Nothing calls it yet; the `title` column on sessions and the callers are tracked separately. See [docs/claude-profiles.md](docs/claude-profiles.md).
- Opt-in live probes of the installed `claude` in `crates/coda-providers/tests/live_probes.rs`, to run after every upgrade of it (`CODA_LIVE_TESTS=1`, ignored otherwise, never in CI). They use the login of whoever runs them, the unmodified binary and the `haiku` model, and check the prompt size of each profile, that the init message lists nothing a profile should have removed, that usage and rate limit reports are read, which control requests answer (`initialize` with its account block, `interrupt`, `set_permission_mode`, `set_model`), what a message sent mid-turn does, that `--fork-session` works and that no flag resumes at a message. First run with claude 2.1.296: `full` 26.8k, `project` 22.3k and `lean` 5.2k prompt tokens, which replaces the 35k and 19.5k in earlier notes; a text-only turn queues a mid-turn message. Codex probes are tracked separately. See [docs/live-recording.md](docs/live-recording.md).
- `[providers.codex] persist_threads` (off by default) lets the Codex app-server keep its thread in Codex's saved history. Coda stores the thread id and resumes the thread with `thread/resume` after a daemon restart, instead of replaying the conversation as a text seed cut at 32 KiB. If Codex refuses the resume, a new thread starts with the seed as before, and a rewind forgets the stored thread.
- `git_status` and `git_diff` are new tools for model-API sessions whose folder is inside a working tree, so the model stops paying for a shell prompt to see what changed. `git_status` lists the branch and the changed and untracked files, and `git_diff` shows the unstaged diff, or the staged one with `staged`, optionally for one `path`. Both show only the session's folder and what is below it, even when the working tree starts higher up, and `path` is relative to that folder. They run `git` with fixed read-only arguments and the cleared environment `bash` gets, and never run a program named in the repository's configuration (a file system monitor, an external diff, a text conversion filter, or a clean or smudge filter that `.gitattributes` selects). A path must be relative and inside the workspace, and is taken literally. They need no permission prompt. Output is cut at 1 MiB with a note. A diff that is long is shortened: a run of 50 or more changed lines keeps its first and last 20 and says how many were removed and added, and the full text stays available through `retrieve`. `retrieve` no longer shortens its own answer: before, the full text of a long original came back shortened again under a new id. A folder outside a working tree is not offered the tools. This is the first part of #238; the guarded `fetch` tool follows.
- The README account risk notice no longer says the Anthropic terms are unverified. It cites Anthropic's Legal and compliance page and Help Center article 15036540 (read on 2026-11-08) and states the rules Coda follows: it drives your installed, unmodified `claude` with flags tested against the real binary, you sign in yourself, Coda never sees the token `claude auth login` produces, and an API key reaches `claude` only if you list it in `env_passthrough` (it then bills API rates). It still says Coda has not asked Anthropic to confirm the use, and the OpenAI notice is unchanged.
- `[daemon] continue_after_restart` (off by default) makes a daemon that starts and finds a turn a restart cut short queue a fixed message for that session and start it. The message tells the agent to check whether its last state-changing action took effect before repeating it. A turn that waited on a permission prompt is not continued, a session with waiting messages keeps them, and a session gets at most 3 continuations in 5 minutes.
- `coda usage --history` sums the tokens per day, model and project from the transcripts the vendor CLIs keep: `~/.claude/projects/**/*.jsonl` (or under `$CLAUDE_CONFIG_DIR`) and `$CODEX_HOME/sessions` (default `~/.codex/sessions`), including the `.jsonl.zst` files Codex compresses. It works for sessions Coda did not run, needs no daemon or database, only reads the files, and looks only at token counts, model, time and working folder. It prints one row per day, tool, model and project, a total per tool, and how many lines it could not use or files it could not read. Days are UTC. These are private formats, so a line that does not fit is skipped and counted, symbolic links are not followed and a line over 32 MiB is dropped. Claude Code writes one reply to several lines and copies earlier replies into a resumed session's file, so each reply counts once by its message and request ids, with its largest output. Codex gives a running total, so each report adds the step since the one before, and a forked session's copied reports count once. Codex counts cached tokens inside its input, so `input` here is the uncached input for both tools. There is no cost in dollars. `--history` cannot be combined with `--session`. Zstd files are read with the pure Rust `ruzstd` crate. Both formats were read from real transcripts on a development machine, and no fixture of them is recorded.
- `[providers.claude_code] env_passthrough` now works. The names it lists reach the `claude` child on top of the built-in list, so listing `ANTHROPIC_API_KEY` is the opt-in to an API key (and `claude` then bills API rates, not your subscription). Before, the key was always removed, which restricted a built-in way to sign in. Coda logs a warning when it starts a session with the key passed, the session's `account` event reports `api_key` billing, and `coda doctor` and `coda login` probe with the same environment, so they show it. `CLAUDECODE` is never passed, and a name that is not letters, digits and underscores, or starts with a digit, is refused when the config loads. Coda hands the variable to the unmodified `claude` as it is and does not inspect, log or store the value. See [docs/config.md](docs/config.md#providersname).
- `coda login <claude-code|codex>` hands a missing login to the backend's own CLI. It checks the login first and stops if there is one. Otherwise it asks, then runs `claude auth login` or `codex login` in your terminal with the terminal's input and output and your own environment, and checks the login again. `--yes` skips the question. Coda never sees the browser flow or the token, reads nothing the command stores, and has no login of its own. It exits 70 when you decline, when the command fails, or when the backend is still logged out afterwards. The `accounts` check of `coda doctor` now names this command for a logged out backend. Both vendor commands were found by reading `--help` of claude 2.1.296 and codex-cli 0.163.0, and a real login was not run.
- A Claude Code session now checks its own `init` message against its profile. For `project` and `lean`, a skill or MCP server that is loaded anyway is logged as a warning that names it, and for `lean` so is any tool outside the profile's list. The session goes on. `full` is not checked. See [docs/claude-profiles.md](docs/claude-profiles.md).
- CI fails when a tracked text file has a line that starts with a merge conflict marker (`<<<<<<< `, `>>>>>>> ` or `|||||||`), through `scripts/check-conflict-markers.sh` and its test. A stray marker reached `main` three times before this check. The new [docs/ci.md](docs/ci.md) lists the CI jobs and scripts.
- `session.create`, `session.send` and `session.cancel` take an optional `client_request_id` (reported as the `idempotent_commands` capability, at most 128 bytes), so a client that lost an answer can retry without a second session, a second message or a second cancel. The daemon keeps the answer of each such request in a new `command_receipts` table (database schema version 19) for seven days, and a repeat gets that answer back, even while the first turn runs or after it ended. A turn start writes its receipt in the same transaction as the turn, and so does a new session, so a crash leaves both or neither. A queued or steered send and a cancel write theirs right after the work, so a crash between the two can still repeat that one action. A turn start that fails after its receipt was stored drops the receipt, so a retry starts again. An id reused for another method or session is refused with an invalid-params error, and an empty or longer id is refused. Without an id nothing changes, and the protocol version stays at 1.
- `[providers.claude_code] profile` (`full`, `project` or `lean`) picks how much of Claude Code's own setup a session keeps. A plain `claude -p` sends about 35k prompt tokens before the first message; `project` (the new default) adds `--setting-sources project --strict-mcp-config --disable-slash-commands`, and `lean` also sets a short Coda `--system-prompt`, `--tools Read,Grep,Glob,Edit,Write,Bash` and no settings. `full` is the old behavior. Because `project` and `lean` skip your user settings, set `profile = "full"` if you rely on hooks or allow rules there. If `claude` rejects a flag of the profile, the session ends with a `backend_crashed` event whose `detail` names the flag and points to `profile = "full"`; Coda does not switch on its own. Token sizes come from earlier live measurements and are rechecked by the live probes (#139). See [docs/claude-profiles.md](docs/claude-profiles.md).
- Coda now tells you how a backend session is billed. A new `account` event (capability `account_events`, protocol version stays 1) is sent once at the start of a Claude Code or Codex app server session with `billing` (`subscription`, `api_key` or `other`) and the plan when the backend names it; it carries no email. Claude Code's comes from the `apiKeySource` of its `init` frame and Codex's from `account/read`. The terminal UI shows `warning: this session bills API rates, not your subscription` when an API key backs the login. `coda doctor` has a new `accounts` check that asks each enabled backend's own binary (`claude auth status --json`, and `account/read` through a short-lived `codex app-server` that makes no thread), shows the plan and email, warns for an API key or a logged out backend, and names the login command. Coda reads only what the binary prints, and the probe runs with the same cleared environment a session gets. The Claude probe uses `auth status` instead of the `initialize` request of the stream: against claude 2.1.296 that response carries the account email and plan but no `apiKeySource` or `tokenSource`, and starting a session to ask runs the user's hooks. The Codex shapes come from the schema the installed codex-cli prints and were not recorded live.
- `session.send` takes `mode: "steer"` (reported as the `steer` capability) to add a message to the turn that is running, so the agent reads it before it goes on instead of the client waiting for the turn to end. Claude Code takes it as another user message on its input, which a live check with claude 2.1.296 showed it reads during a running tool and answers in the same turn. The Codex app server takes it as `turn/steer` naming the running turn. A model-API session adds it to the conversation at its next step, after the results of the calls in flight, and a message that arrives as the model is about to finish keeps the turn going. The Codex exec backend cannot take one and refuses. A steer with no turn running is refused, the message is stored in the turn as a `user_message` with `steered: true`, and the result has `steered: true`. A model-API turn that ends before it reads a steer queues it to start as the next turn. A message that reaches Claude Code or Codex as the turn ends may not be read. `coda session send --steer` uses it. The protocol version stays at 1. The terminal UI does not use it yet. Because Claude Code steers on its own, the fallback of stopping and starting an attempt again, with an `attempt` column on turns, was not needed.
- `/diff` in the terminal UI opens a colored, scrollable, searchable unified diff of the last turn, and a turn that changed files ends with a line such as `changed 3 files +12 -4 (/diff)`. It reads the turn through `session.diff`, so it needs a daemon that reports the `diff` capability and says so when it does not.
- A new `session.diff` method (capability `diff`; the protocol version stays at 1) lists the files one turn changed and, on request, returns the unified diff. It compares the checkpoints around the turn, so the index and `HEAD` stay untouched, and it leaves out files that only came in with a pull, merge or rebase during the turn. It lists at most 1000 files and cuts the diff at 512 KiB.
- The Codex app server backend now reports plan limits. On the first turn of a session it asks `account/rateLimits/read` and sends the result as a `rate_limit` event, and it sends another for each `account/rateLimits/updated` notification. A window is named `five_hour` or `seven_day` by its length and any other keeps the slot name `primary` or `secondary`; usage is in basis points, as for Claude Code. A turn that ends in error because Codex says `usageLimitExceeded` sends a `usage_limit` event just before its `result`, so a `coda review` part can move to Claude Code when Codex runs out. The shapes come from the schema the installed codex-cli prints and were not recorded live, and a server that refuses the read still runs the turn. Codex exec does not report limits yet (#325).
- `session.send` takes `mode: "queue"` (reported as the `queued_sends` capability) so a message sent while a turn runs is kept instead of refused with `TurnError::Busy`. It is stored in the database (schema version 18), at most 32 per session, and starts when the running turn ends cleanly, one after another. A turn that was cancelled, failed, hit a usage or token limit, or was cut short by a restart starts nothing: the messages stay stored until the client sends `session.queue` with `action: "resume"`, or sends a new message that ends cleanly, which then starts them behind it. A queued message keeps its `max_turns` and `token_cap`, may hold at most 64 KiB of text, and nothing starts while the daemon shuts down. A send in `queue` mode to a free session with nothing waiting starts at once, and a result with `queued: true` names the latest turn the message waits behind. A new `session.queue` request lists the waiting messages, resumes them, or discards one by id, which is how a client edits its last message. `coda session send --queue` sends in this mode. The default mode is unchanged and still refuses while a turn runs, and the protocol version stays at 1. The terminal UI does not use it yet.
- `/sessions` and Ctrl+K in the terminal UI open a session picker instead of printing one line per session. It lists the sessions that wait for you first (approval needed, input needed, working), then the rest, newest first, with the first message as the title, the backend and the age. Typing narrows the list, Enter resumes and Esc closes. To feed it, `session.list` results now carry `attention` (`none`, `approval` or `input`, a question outranking an approval) and `title` (the start of the first message, up to 80 characters); a client that does not know them reads them as absent, and the protocol version stays at 1. The failed, plan ready and completed states of the issue need a record of what each client has seen, which no part of the daemon keeps yet, so they come later.
- `coda changelog` proposes one entry for the `Unreleased` section of `CHANGELOG.md` from the branch diff and commit messages, using a new built-in `scribe` agent, and prints the entry with a short diff. It writes only with `--write` and a confirmation, never commits, refuses a file it cannot read or that has no `## [Unreleased]` heading before it asks the model, writes nothing for an empty or malformed answer, and marks the entry with a comment so a second run for the same branch adds nothing.
- Tab in the terminal UI prompt completes an `@path` word against the session's folder. One match completes the word, several complete to their common start and list up to eight names, a directory ends in a slash, and hidden entries (unless the word starts with a dot), `.git`, symbolic links, names with white space or control characters, and paths outside the folder are not offered. Matching is case sensitive, and a cursor inside a word completes nothing.
- `coda describe` drafts a pull request title, summary and a note for each file with a new built-in `describer` agent, and prints them. With `--labels` it also suggests labels, only from the new `[[describe.labels]]` config list (each with a `use_when` line) that the repository has, and drops any other. It writes nothing unless you pass `--apply` on a pull request: after a preview and a `y` (or `--yes`), the draft goes in the body between `<!-- coda:describe:start -->` and `<!-- coda:describe:end -->`, so a rerun replaces only that block and keeps your text, and the suggested labels are added. It never removes a label or changes the title. See [docs/config.md](docs/config.md#coda-describe).
- `coda review --context-file <path>` (up to 5) adds test, coverage or linter output to the prompt in blocks marked as untrusted data, each cut at 20000 characters, with `--context-note <text>` for one line on how to use it. `--run-checks` first has the `tester` agent run the commands in the new `[review] check_commands`, on a model-API backend with your standing grants, and adds its report the same way; a tester that fails leaves a note and the review goes on. A review also prints a run report on standard error (backend, model, wall time, parts, fallback, verifier, and tokens only when a backend gave them) and adds it as a line of JSON, with no diff text, to `review-runs.jsonl` in the data directory. See [docs/config.md](docs/config.md#coda-review).
- The terminal UI prompt is now a composer. It takes several lines (Alt+Enter, Ctrl+J, or Shift+Enter with the kitty keyboard protocol, which the UI now asks the terminal for), grows up to six rows, shows a cursor and lets you move and edit with the arrow keys, Home, End, Delete and the usual Ctrl and Alt chords. Up recalls earlier prompts only while the line is empty or unedited, and Ctrl+S stashes a prompt and brings it back on an empty line. Esc clears the prompt but keeps the draft in the stash. A paste has its invisible characters removed with a warning (a zero-width joiner stays between two shown characters), and a paste of 32 KiB or more is written to a new private file under `.coda/pastes/`, with its tabs kept, and replaced in the prompt by a pointer the agent can read. Git ignores that folder and the next large paste removes files older than a week. Before this the prompt was one line that could only append and delete at its end, and a paste was flattened to one line.
- `coda checkpoints prune` and a `checkpoints.prune` request (error code -32009 when applying is refused). Every checkpoint ref under `refs/coda/checkpoints/<session>/` kept its commit and every new file alive for good, so the git object store grew with each turn. The command lists the refs that can go, with the space only they hold, and changes nothing; `--apply` removes them, and only while `[checkpoints.prune] enabled` is true, which is off by default. A turn checkpoint goes when it is beyond the newest `keep_turns` (50) or older than `keep_days` (30), and a rewind's `pre-rewind-*` save goes after `rewind_days` (7). Only refs this database recorded are touched. The `base` ref, a session's newest live turn, refs with other names, and every ref of a session with a running turn stay. A removed ref is forgotten on its turn, so a rewind to that turn says it has no snapshot. Coda does not run `git gc`; git collects the objects later. See [docs/config.md](docs/config.md#checkpointsprune).
- `[review.routing]` picks the model for each part of a `coda review` by its size: rules with `max_hunks`, `max_files` and `max_chars` are tried in order, the first that fits sets the model, and with no match the backend keeps its own default. The model reaches model-API backends only; Claude Code and Codex keep their own default until their launch takes a model (#324). A part that hits a usage limit, or whose backend process is lost, runs again on the other of Claude Code and Codex when that one is enabled (`fallback`, on by default), and the review names each move under `Fallback` and in `run.fallbacks`. Only Claude Code reports a usage limit today (#325). With no backend left, the part fails: the review is partial, as for any failed part. Only the global config sets it. See [docs/config.md](docs/config.md#reviewrouting).
- `coda worktree clean` and a `worktree.clean` request (error code -32008 when it is refused). - `write` and `list` tools for model-API sessions, so the model can create a file and look at a directory without `bash`. `write` creates a new file, and replaces an existing one only when the session read it with `read` and it has not changed since; it never creates directories and stops at the same 1 MiB cap as `edit`. `list` shows one directory (folders end in `/`), or with a `pattern` such as `*.rs` or `src/**/*.toml` searches the tree by name, and skips `.git`, `target` and `node_modules` like `grep` (`include_dirs` opts them back in). Both stay inside the workspace and refuse symlinks. In `accept-edits` mode `write` is allowed like `edit`, except for files that change what runs. Both names can be used in an agent's `tools` list. See [docs/agents.md](docs/agents.md).
- Building blocks for `coda review` in the `coda-review` library: reading the staged diff, finding the default branch (`origin/HEAD`, else `main`, else `master`), reading what the user typed as a pull request, branch or range, the prompts and reply format for the reviewer, and the step that turns checked model output into a finished review.
- A diff packer for reviews, in the `coda-review` library. It reads the diff, drops binary, vendored and ignored files and deletion-only hunks (naming deleted files), orders files by the repository's main language then by size, adds three lines of context and the new-side line number to each line, and keeps the text within `[review] diff_budget_chars` (default 120000). The file the budget cuts is clipped at a whole line, even inside a single large hunk, and the files after it are left out. Both are named in the coverage list. See [docs/config.md](docs/config.md#review).
- Review ignore and skip rules. `[review.ignore]` takes globs (with `**/`) and a built-in list of generated files (lockfiles, minified files, source maps, generated protobuf). `[review.skip]` skips a pull request by draft state, label, title regex, source or target branch regex, author or bot author; the library decides skip or review and builds the one-line reason, and a force flag overrides it. `coda review` prints that line, exits 0 and takes `--force`. Rules come from the global config and `.coda/review.toml` on the default branch (given as a `refs/heads/` or `refs/remotes/` ref such as `refs/remotes/origin/main`), and a rules file on the pull request's own branch is ignored. See [docs/config.md](docs/config.md#reviewignore).
- A `coda-review` crate with the review finding schema (id, file, line range, severity, category, title, explanation, optional patch, confidence), a strict parser for model output that rejects a finding whose lines fall outside the diff and builds a bad-shape retry hint, a coverage list that names every file given to the packer, and markdown and JSON renderers. Model text in the markdown output cannot start headings, rules, code fences, HTML tags or mentions, also inside list items and quotes. `[review] max_findings` (default 5) caps the findings kept per run. See [docs/config.md](docs/config.md#review).
- A Claude Code session keeps what the CLI reports about usage and limits. The `result` line's token counts (input, output, cache read and cache write) become a `usage` event, and each `rate_limit_event` becomes a `rate_limit` event with the status, the window and its reset time, per-window utilization in basis points, and the overage fields. `initialize` reports the `usage_details` and `rate_limit_events` capabilities. The field names come from a live recording on claude 2.1.296.
- A turn that ends in error after a rejected rate-limit report now sends a `usage_limit` event just before its `result`, naming the window (`five_hour`, `seven_day`, `model_scoped`, `monthly`) and when it resets, so a client can say the plan limit was hit and when it lifts. `initialize` reports the `usage_limit_events` capability, and `PROTOCOL_VERSION` stays 1.
- `initialize` returns `capabilities`, optional flags such as `usage_details` and `rate_limit_events` that default to false when absent, and an event type a peer does not know reads as `unknown` instead of failing. A new event no longer needs a `PROTOCOL_VERSION` bump; only a breaking change does.
- A release workflow that builds, checksums and attests the `coda` archives for Linux and macOS, and an `install.sh` that verifies the checksum before installing.
- A `session.close` request that stops a session's idle Codex server or model conversation and keeps its stored events. `coda run` calls it when the turn ends, and the terminal UI calls it for a session it created when the user quits or switches away.
- A `cause` on `turn_interrupted` events (`cancelled`, `idle_timeout`, `backend_lost`, `daemon_restarted`, `daemon_stopping`). `coda run` exits 4 for a turn cancelled from another client and 5 for the other causes, naming the cause.
- `daemon.status` reports `any_provider_enabled`, so the terminal UI shows the setup guidance when a daemon that started before `coda init` has no provider.
- Agent, skill and command definition files with a loader, `coda agents list` and `coda agents trust`. Project definitions load only after the repository is trusted, and trust ends when they change. See [docs/agents.md](docs/agents.md).
- `[[hooks]]` in the user's `config.toml`: programs coda runs at `session_start`, `pre_tool` and `post_tool` in a model-API session. A hook gets a JSON payload on standard input and a minimal environment without API keys. It is killed with its process group at its timeout, and only a `blocking` hook can stop the action it guards. See [docs/config.md](docs/config.md#hooks).
- `coda agents lint` checks definition files for unknown tiers, efforts and tools, missing usage guidance and model ids, and a `[routing]` config table maps agent tiers to models.
- A `task` tool that runs a named agent as a child conversation with only its tools, its tier's model and its own permission prompts, which reach the parent's client with the agent named in the `agent` field of `permission.request`, and the terminal UI draws it apart from the command. See [docs/agents.md](docs/agents.md).
- A `task` result reports a status (`completed`, `failed` or `cancelled`), a summary and findings classified as blocking, non-blocking or suggestion. The agent's words are marked as data and capped at 16 KiB with the findings kept whole, blocking first, and a malformed report is rejected. A `task` call with a blank prompt is refused.
- Built-in agents `explore`, `reviewer`, `implementer` and `tester`, available to the `task` tool with no files. A user file of the same name replaces one. A trusted project file of the same name can replace its prompt and narrow its tools, but keeps its tier and effort; `coda agents lint` reports a tier, effort or tool the project file asked for and did not get.
- Command files are slash commands in the terminal UI (`/name args`, listed by the new `/help`) and run headless with `coda run --command <name> --args <text>`. Without `--args`, piped standard input (up to 256 KiB) is the arguments of a command that has a `$ARGUMENTS`; an unknown command fails before it is read, and a command without `$ARGUMENTS` never reads it. `$ARGUMENTS` in the prompt template is replaced by the arguments as plain text, and a prompt that is blank after that is not sent. Only your own and trusted project commands run, and a built-in TUI command wins a name clash in the TUI. The terminal UI reads trust once, when it starts. It says when definition files were skipped.
- Skills for model-API sessions. The model is offered the skills by name and description in the description of a new `skill` tool, and a skill's body enters the conversation only when the model calls the tool for it. Only your own skills and those of a trusted project are offered.
- `coda doctor` warns when a `[routing]` alias uses another provider than the default session provider, since a `task` call in a session on that provider cannot use it.
- Provider keys `max_output_tokens` (for `anthropic` and `openai_compat`), `max_tokens_field` (`"max_tokens"` or `"max_completion_tokens"`) and `stream_usage` (for `openai_compat`), so a server that rejects `max_tokens` or `stream_options`, or a small local model that cannot fit an 8192-token reply, can be used. The defaults keep the request as it was. See [docs/config.md](docs/config.md).
- A licensing page, [docs/licensing.md](docs/licensing.md), covering the Apache-2.0 license, the source header check and the dependency license policy.
- `AGENTS.md` at the repository root holds coda's rules for tests, code, writing, commits and pull requests, so a person or an agent working in the repo sees them. They had lived outside it. A script test (`scripts/tests/agents-md.test.sh`) fails when a script or doc it names goes missing or CI stops running one of the three cargo checks it lists, and `coda review` reads the file as the repository's guidance. The CI jobs are described in [docs/ci.md](docs/ci.md).

### Changed

- The release workflow now unpacks each archive it builds and runs `scripts/smoke-binary.sh` on the binary inside: it must print its version and migrate a database written by schema version 1 to the current version without losing a session. A broken archive fails the run before publish. The Intel macOS archive is cross-built on an arm64 runner that cannot run it, so it is built and checked with `lipo` for its architecture but not run. See [docs/release.md](docs/release.md).
- CI has a final `check` job that needs every other job and runs even when one fails or is cancelled. It fails unless every job succeeded (`scripts/ci-aggregate.sh`, tested by `scripts/tests/ci-aggregate.test.sh`), so branch protection can require `check` alone and a new job joins it by being added to `needs`. A job renamed or removed no longer leaves a stale required status.
- Coda is now licensed under Apache-2.0. It was AGPL-3.0-only. Every source header, the workspace license field, `NOTICE`, `deny.toml` and the SPDX check use the new identifier.
- `clippy.toml` now disallows `std::thread::sleep`, so a blocking wait in tests or code must wait on an event, use a `Sleeper` seam, or carry `#[expect(clippy::disallowed_methods, reason = "...")]`. Async `tokio::time::sleep` is not covered. Integration tests that polled a child process in a sleep loop now block on it through `coda_testkit::wait::output_within`, which kills the child at the limit. Waits with nothing to block on (a file appearing, a process that is not our child exiting) go through `coda_testkit::wait::poll_until`. `Instant::now` and `SystemTime::now` are not banned yet (#340).
- `[workspace.lints.clippy]` now sets `allow_attributes = "warn"` and `allow_attributes_without_reason = "deny"`, so a lint suppression must be an `#[expect(..., reason = "...")]` that says why. An unneeded one warns, which fails CI. The shared `tests/common` modules keep `allow(dead_code)` with a reason, because each test binary uses a different part. One `too_many_lines` suppression in the protocol schema was not needed and is gone.

### Fixed

- The bundled SQLite is now 3.54.0 (`rusqlite` 0.41.0, `libsqlite3-sys` 0.39.1), which clears RUSTSEC-2026-0459 that `cargo deny` reported against the earlier bundled copy. The release lowers the minimum Rust version and changes no API Coda uses, and the database schema is untouched.
- `git_status` and `git_diff` now read `git --version` once and refuse to run when git is older than 2.44, or when the version cannot be read. The overrides that stop a repository's programs from running (`GIT_CONFIG_COUNT` from 2.31, `GIT_NO_LAZY_FETCH` from 2.44) are ignored without a message by an older git, so such a git could run a clean filter or a transport program. The call fails with an error that names the minimum, and no repository command runs. Closes #409.
- The text about `coda session ship` no longer says your sign-off applies. The commit runs plain `git commit`, so it is signed when your git is set to sign and has a sign-off only when a hook of yours adds one. Tests now check the signature and the trailer (#405).
- A pull request link recorded from a model-API session's shell output now has three checks. The command line must run `gh pr create` itself, not name it in a string, and a line with a backslash, backtick, parenthesis, brace, `<` or `#` is not read at all, the address must be on the same host as the `origin` remote of the session's folder, and a session keeps at most 20 links. It is a best-effort guard, because a command can still print an address on that host (#404).
- Scheduled prompts are bounded and show their failures (database schema version 24). A run that fails to send now leaves its reason and time on the schedule, shown by `coda schedule list` and in `schedule.list` as `last_error` and `last_error_at` until the next run starts (#396). A failed send into a new session no longer leaves an empty session behind (#397). A schedule that makes a new session for each run ends after 50 runs, a finished schedule is deleted after 7 days, and the list holds at most 200, live ones first (#403).
- The text of an incremental review that wakes a session for a pull request watch now has its control and invisible format characters removed and every line that starts with the letters `PR watch`, whatever its case, spacing or markup, dropped, and the wake message says the text comes from a review of a pull request whose content its author controls. Before, the author could put escape codes or a forged wake header in the diff and have it reach the agent unchanged (#399).
- A scheduled prompt and a pull request watch wake now put back the folder of a session whose worktree `coda worktree clean --apply` removed, as a message you send does. Before, the send failed and was only logged, and a one-time schedule was lost (#402).
- `coda session ship` no longer runs `git add --all`. It commits what is already staged, so an untracked env file, unrelated work or a partial index you built is not swept into the commit or pushed. It lists the committed files in its result (`files`), and the new `--all` flag (`all` in the request) stages every change first, as before. With nothing staged and no `--all` it refuses and says so (#401).
- Accept-edits mode now asks before an edit, write or multi-edit touches anything under a `.git` directory, a `.git` file or a `.gitattributes` file, at any depth. Before, only `.git/hooks` was guarded, so a write to `.git/config` could set `core.hooksPath` or `core.fsmonitor` and run code on the next git command, including the one `session.ship` runs (#398).
- `git_status` and `git_diff` could run a clean filter whose name holds an equals sign (`filter=a=b` in `.gitattributes`, `filter.a=b.clean` in the repository config), because the switch that emptied it was split at the first `=` and never reached the real setting. The overrides now go in through `GIT_CONFIG_COUNT`, `GIT_CONFIG_KEY_n` and `GIT_CONFIG_VALUE_n`, which take a key whole (git 2.31 or later). Tests also cover filter names with dots, commas, colons, backslashes and empty parts, and show that a program variable in the caller's environment, an included config file and a diff driver `command` run nothing. A second hole is closed too: in a partial clone, a missing object made `git_diff` fetch through the remote's transport program (such as `core.sshCommand`), so the tools now set `GIT_NO_LAZY_FETCH=1` (git 2.44 and later), and they drop the caller's `GIT_CONFIG_COUNT` and `GIT_CONFIG_PARAMETERS`.
- A Codex plan window of 43200 minutes (30 days) is now named `monthly`, in whichever slot Codex reports it, instead of `primary` or `secondary`. The terminal UI then shows it as `mo` with its pace of use, and `usage_limit` maps it to the monthly window kind.
- The model-API fence test (#285) no longer starts its busy store from a polling thread that could run late and let the test pass without the fence. A new test sends text and then a fence through the loop's own publisher and checks the fence is still waiting before the text is stored. It failed in 56 of 56 loaded runs when the model arm of the fence returned at once, and passed in 104 of 104 with the fence. The old test's thread and `sleep` are gone, and what is left of it checks the order of events end to end (#292).
- The daemon test `the_first_turn_is_compared_with_the_baseline_taken_before_it` no longer fails now and then in the coverage job. A coverage run makes the fake backend write an empty `.profraw` file into the session folder at no fixed point of a turn, and when it landed inside the first turn the turn's diff held it. The test repository now ignores `*.profraw`, so no checkpoint holds one, and the diff tests no longer filter it from the file list by hand. With coverage-instrumented binaries the test failed in 7 of 96 loaded runs before, and no test of the diff and checkpoint modules failed in 192 loaded runs after (#352).
- The hook test `a_bare_program_name_is_found_on_the_path_the_hook_was_given` no longer runs a script it wrote a moment before. Under load the first run of a new file took longer than the hook's 15 second limit and the hook timed out (300 at once: 230 timed out). The test now finds a link to an installed program through its bare name, which still shows that the name is looked up on the hook's `PATH` (#291).
- A checkpoint no longer holds the old content of a file that was edited to the same size within a second of git writing the index. The snapshot works on a copy of the index, and a copy with a newer modification time hid git's own check for such files; the copy now keeps the time of the original. Seen as a flaky test on Linux, where the copy gets a new time.
- A Claude Code process that dies while a permission prompt waits is now noticed at once. The adapter read nothing from the process while it waited for the answer, so the crash showed only after the user answered, and the prompt kept live keys that reached nothing.
- A forced stop now works on a stuck model-API turn. It used to kill nothing, because the turn has no backend process, and the terminal UI kept showing `Forcing stop`. The daemon now gives up on the turn task, records the turn as cancelled and frees the session, and the next send rebuilds the conversation from the stored events. Streamed text that was not stored yet when the force landed can be lost, and a store that does not answer within 5 seconds is given up on so the session is freed. The terminal UI also checks the `force_cancel` capability, and offers the force again when a force did not end the turn.
- A `session.cancel` on a Claude Code or Codex `exec` turn no longer waits behind a full event queue (a slow store). The adapter now watches the cancel while it hands over an event, stops the backend first, and then sends the interrupted event. Events already queued are kept and stored in order.
- The test `a_store_user_is_not_blocked_while_the_index_walk_runs` failed once on a busy machine because it compared the single slowest store call with half the walk, so one pause of the test runner failed it. It now checks that a store call finishes in the middle of the walk, as the definitions test does.
- On a model-API session, a `permission_request` could be stored before the text and the assistant message that came just before it when the store was slow, because the announcement did not wait for the daemon to store the loop's earlier events. The loop's event channel now carries a marker, and the announcement waits until the daemon answers it, so the log keeps the order the loop produced.
- On Claude Code and Codex sessions, a `permission_request` could be stored before the text the backend streamed just before asking, because the announcement skipped the 50 ms text coalescing queue. The announcement now waits until the queued events are stored, so the log keeps the order the backend produced.
- In `accept-edits` mode, `edit`, `write` and `multi_edit` now also ask before changing a build, package or task-runner file that runs code later: `Makefile`, `justfile`, `package.json`, `pyproject.toml`, `setup.py`, `tox.ini`, `build.gradle`, `pom.xml`, `CMakeLists.txt`, `Rakefile`, `Gemfile`, `Dockerfile`, `Taskfile.yml`, `.envrc`, `.npmrc` and similar, at any depth and whatever the letter case. All three tools already shared one list; it only held the Rust files. A grant does not override the prompt.
- A model-API session stored one `stream_delta` row for every streamed chunk of text. It now joins chunks that arrive within 50 ms into one row (a row stops growing at about 16 KiB), as Claude Code and Codex turns already do, and stores any other event only after the text streamed before it.
- The database no longer keeps the `first_turn` and `last_turn` columns of `backend_threads`, which were written and never read, and the unused helper that marked a stored backend id as failed is gone. A new migration step (schema version 12) drops the two columns and keeps the stored ids. A test now covers the `history_not_restored` event for a Claude Code session whose stored conversation cannot be read.
- The test `a_timed_out_check_takes_its_children_with_it` failed on a busy machine because it asked `kill -0` about the child a moment after the kill, while the process was still exiting. It now waits for the end of a pipe that only the script and its child hold open, so it needs no polling and no process id.
- The `initialize` example in the protocol golden files now shows `rate_limit_events` true, as the daemon sends it, and a daemon test compares the real result with it. `Event::Unknown` is documented and tested as receive-only (it serializes as `{"type":"unknown"}`, so a relay must not store or forward it). A Claude rate-limit window with no numeric utilization, or a reset time that is not whole seconds (a fractional, negative or millisecond value), is now noted in the parser diagnostics instead of dropped silently, and a whole-number float reset time is accepted. The `Capabilities` docs say each flag means the daemon can send the event, not that every backend does, and utilization docs say it can exceed 10000 basis points.
- The review library reads quoted and escaped file names correctly (`git ls-files -z`, octal escapes in diff headers), clips a single hunk larger than the budget at a line instead of dropping it and every file after it, keeps model text from forging headings, mentions or HTML in the markdown output, merges touching line ranges, reads the rules file only through a `refs/heads/` or `refs/remotes/` default branch ref, cleans control characters out of diff lines, accepts leading-slash ignore globs and caps the model text in the retry hint.
- The daemon turn tests wait for a permission request's announcement before answering it. The request row is written before its `permission_request` event, and an answer in between suppresses the event by design, so a slow run could answer first and the burst test found no `permission_request`. No daemon code changed.
- A backend turn no longer loses events when it emits faster than the store writes. The event queue used to drop events once 1,024 were waiting, which could remove a result or a permission request from the log. Nothing is dropped now, and text streamed within 50 ms is stored as one chunk.
- A slow store no longer lets a turn's event queue grow without limit. The queue between a backend and the publisher holds at most 1,024 events, and a backend adapter waits to hand over its next event when it is full, so the backend's own pipe fills and it slows down. No event is dropped.
- An event waiting for room in the turn's queue is no longer lost when the turn is cancelled or the idle timeout fires at that moment. The event stays in the sink and is sent before the next one and at the end of the turn. A turn whose event the store could not write now ends as failed, with an error in the event log. After an idle timeout, a store that does not answer for 30 seconds no longer holds the session: the turn lets go and logs what it could not store.
- A Claude Code session keeps its conversation across a daemon restart. The backend's own session id is stored in a new `backend_threads` table, so the first send after a restart resumes it instead of starting with no context. An id the backend fails to resume twice in a row, before it names any conversation, is dropped and the session starts fresh; a single early crash keeps the id and tries it again. Codex thread ids are not stored yet.
- A Claude Code session id is now stored when the backend first reports it, so a daemon killed mid-turn still resumes the conversation. When the backend refuses a stored id, the fresh start is sent the stored conversation before the prompt, as a Codex thread is, or a `history_not_restored` event when it cannot be read.
- A Claude Code session no longer loses its stored conversation to one crash at start-up. The stored id is kept until a resume fails twice in a row before the backend names a conversation, and it is replaced when the fresh start names a new one. The stored history is sent with the prompt only once: a retry after the fresh start has named its conversation does not add it again. The write that stores the id no longer pauses reading the backend, and the history sent to a fresh start is capped by its size as rendered JSON, so escaped text in the history cannot exceed the 32 KiB cap.
- Esc no longer quits the terminal UI. It clears the input, or denies a permission request when one is open. Quit with `/quit`, Ctrl+D on an empty input, or Ctrl+C twice within two seconds when idle. Ctrl+C still cancels a running turn.
- The terminal UI quit hints are now true and fit a narrow terminal. A paste between two Ctrl+C presses resets the quit confirmation, the confirmation and a new busy-turn hint show on the connection line and expire instead of stacking in the transcript, and Ctrl+D quits after the daemon is lost even with text left in the input.
- A skill body between 16 and 32 KiB reaches the model whole. It was shortened like any long tool result.
- A `task` call for an agent whose definition file was skipped is refused with the problem. It used to run the built-in or user agent of that name without a word.
- A result that a hook withheld no longer leaves its original in the store when saving its size failed, and deleting it no longer waits for the store on the async threads.
- The daemon holds the store only to read the trust decision when it reads definition files, instead of for the whole read, and reads them once per send, so the skill index and the `task` agent list come from the same files.
- A model-API session that is revoked, or whose project agents change, rebuilds its conversation at the next send even when it has no skills, so the `task` tool no longer lists an agent the repository stopped trusting.
- A session keeps the tokens it spent, and its send limits, when the daemon drops its idle conversation to make room, and keeps the tokens after a daemon restart. It used to start again with a full budget.
- The warning about skipped definition files is logged once per built conversation and again only when the number of skipped files changes, not at every send.
- A `task` call that runs a built-in or user agent while a held-back project file has the same name ends its result with a note saying so.
- A store error while reading the trust decision leaves the built-in agents in the `task` list and in dispatch, and is logged, instead of failing the send. A session that already has a conversation keeps it for as long as the read keeps failing.
